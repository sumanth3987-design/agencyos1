**Audit Date:** October 31, 2026  
**Application Environment:** Python 3.10+ / Flask / SQLAlchemy

## 1. Executive Summary
This report documents all database-level unique constraints, partial indexes, and idempotency safeguards active in AgencyOS. It includes the verified fund-flow columns added via `apply_fund_flow_columns.py` to prevent duplicate billing, payment race conditions, and talent payout leakage.

## 2. Table-by-Table Uniqueness & Index Inventory

### Table: `user`
- `id` (INTEGER, Primary Key)
- `email` (VARCHAR(120), Unique, Not Null) — Guarantees single-tenant identity per email address.

### Table: `user_token`
- `id` (INTEGER, Primary Key)
- `token_hash` (VARCHAR(64), Unique, Not Null, Index) — Prevents replay attacks on one-time magic login and password reset links.
- `ix_user_token_user_purpose` (Composite Index: `user_id`, `purpose`) — Accelerates lookup and revocation of outstanding tokens.

### Table: `customer_profile` & `professional_profile`
- `user_id` (INTEGER, Unique, Foreign Key to `user.id`) — Enforces a strict 1:1 relationship between an identity record and their operational profile.
- **New Banking/Payout Fields in `professional_profile` (Added 10/31/2026):**
  - `upi_id` (TEXT)
  - `bank_account_number` (TEXT)
  - `bank_ifsc` (TEXT)
  - `pan_number` (TEXT)

### Table: `payment` (Razorpay Idempotency Engine)
The `Payment` table implements three database-level uniqueness guards to eliminate double-charging and duplicate credits:
1. `uq_payment_razorpay_order_id` (Unique Constraint on `razorpay_order_id`) — Guarantees an order generated by the Razorpay API cannot be duplicated.
2. `uq_payment_razorpay_payment_id_partial` (Partial Unique Index on `razorpay_payment_id` WHERE `razorpay_payment_id IS NOT NULL`) — Prevents duplicate payment capture events from credit/debit/UPI callbacks.
3. `uq_payment_project_customer_created` (Partial Unique Index on `(project_id, customer_id)` WHERE `status = 'Created'`) — Guarantees at most one open/pending payment intent per project milestone at any given time.

### Table: `invoice`
- `id` (INTEGER, Primary Key)
- `invoice_number` (VARCHAR(100), Unique, Not Null) — Enforces statutory sequential numbering (`INV-YYYY-XXXX`).
- `project_id` (INTEGER, Foreign Key to `project.id`, Unique via 1:1 backref) — Links one primary invoice record per project milestone.
- **New Payout Tracking Fields in `invoice` (Added 10/31/2026):**
  - `payout_status` (TEXT, Not Null, Default: `'Pending Approval'`) — State-machine: `'Pending Approval'`, `'Ready to Pay'`, `'Paid'`.
  - `payout_utr` (TEXT) — Bank Transaction Reference (UTR) recorded upon manual or automated IMPS/UPI disbursement.
  - `payout_paid_at` (DATETIME) — Exact timestamp of fund disbursement.
